## Overview

A modular Python pipeline for processing raw triaxial accelerometer data from the **ActiGraph wGT3X-BT** device. Implements the ActiGraph count algorithm, intensity classification using validated VM thresholds, non-wear detection, and a heuristic cycling detection algorithm. Delivered as a Streamlit web application with interactive visualisation, manual annotation, and publication-ready figure export for thesis writing.

The processed outputs are designed for downstream statistical analysis in R (`main.Rmd`).

> **Cite this software:** See [`CITATION.cff`](CITATION.cff) or use the *Cite this repository* button on GitHub.

## Input Data Format

The application accepts two input formats:

**CSV file** (daily accelerometry data from `GT3X_to_CSV.ipynb`):

| Column | Description |
|---|---|
| `X` | Acceleration on the X axis (g) |
| `Y` | Acceleration on the Y axis (g) |
| `Z` | Acceleration on the Z axis (g) |
| `timestamp` | Datetime string *(optional — defaults to 08:00 if absent)* |

**`.agd` file** (ActiGraph database, SQLite format — multi-day recording with day navigation):

The application reads `.agd` files directly, extracts all recording days, and provides a day selector in the sidebar for navigation between days.

---

## Raw Data — Important Note

The original `.gt3x` binary files are **not included** in this repository due to their size (> 20 GB per participant). To reproduce the full workflow from raw recordings, use `scripts/GT3X_to_CSV.ipynb`, which:

1. Reads a `.gt3x` binary file using the `pygt3x` library
2. Reconstructs absolute timestamps from the recording start date
3. Splits the data into one CSV file per calendar day
4. Exports to `data/<filename>/` — directly compatible with `app_euromov.py`
5. Runs a verification check to ensure no samples are lost

> Additional dependency: `pip install pygt3x tqdm`

## Pipeline Description

Implemented in `sources/pipeline.py` — importable independently of Streamlit.

### 1. Count Calculation
Raw acceleration is processed via the ActiGraph algorithm ([agcounts](https://github.com/actigraph/agcounts)): resampling to 30 Hz → 7th-order IIR bandpass filter → rescaling → epoch summation.

The **Vector Magnitude** (VM) is computed as:

$$VM = \sqrt{X^2 + Y^2 + Z^2}$$

Applied to counts per epoch (Sasaki et al., 2011).

### 2. Activity Classification

| Class | VM threshold (cpm, 60 s epoch) | Reference |
|---|---|---|
| Sedentary | < 200 | Aguilar-Farías et al. (2014) |
| Light | 200 – 2 690 | Sasaki et al. (2011) |
| Moderate (Walking) | 2 691 – 6 166 | Sasaki et al. (2011) |
| Vigorous (Running) | ≥ 6 167 | Sasaki et al. (2011) |

Thresholds scale proportionally to the chosen epoch size.

### 3. Smoothing
A 60-second centred modal sliding window reduces spurious transitions between classes.

### 4. Non-Wear Detection
Epochs are reclassified as *Non-Wear* when VM remains below the quasi-immobility threshold for a continuous 90-minute sliding window (Choi et al., 2011).

### 5. Cycling Detection
A three-criterion heuristic detects cycling without GPS, designed for **hip placement**:

| Criterion | Threshold | Empirical recall | Reference |
|---|---|---|---|
| Spectral peak in pedalling band [0.5–2.0 Hz] (FFT on Z axis) | ≥ 0.08 | 98.9% | Brage et al. (2005) |
| Low VM variability over 3 epochs (CV) | < 0.55 | 97.8% | Mannini & Sabatini (2010) |
| VM in cycling-compatible range | 200 – 6 167 cpm | — | Sasaki et al. (2011) |

> ⚠️ Heuristic detection — no GPS. Thresholds calibrated empirically on real cycling data (hip placement, wGT3X-BT, 60 Hz). Adjustable in the sidebar for individual calibration.

## Application Features

### Streamlit Tabs

| Tab | Content |
|---|---|
| 📊 Time Profile | Stacked bar chart of activity distribution over time |
| 🎯 Global Summary | Donut chart (time budget) + radar chart (motor fingerprint) |
| 🧪 Statistics | VM boxplot by class + Mann-Whitney U test (Light vs Moderate) |
| 📋 Session Details | Continuous session inventory per activity type |
| 🚴 Cycling Detected | Cycling epoch timeline and session table |
| 🔬 Cycling Diagnostic | Per-epoch FFT/CV/VM criterion values for threshold calibration |
| ✏️ Manual Annotation | Annotate time ranges, compare with detected classification (accuracy, F1, Cohen's κ) |
| 📁 Participant Summary | Valid wear days (≥ 10 h), session counts, dominant time slots per activity |
| 🖼️ Figure Export | Generate publication-ready PNG figures for thesis |

| File | Content | Thesis section |

| Parameter | Description |
|---|---|

## Using `pipeline.py` Independently

The processing module is fully independent of Streamlit and can be used in any Python script or Jupyter notebook:

```python
import pandas as pd
from sources.pipeline import (
    executer_pipeline_agcounts,
    ajouter_temps,
    lisser_activite,
    detecter_non_port,
    detecter_velo,
    extraire_sessions,
)

df_brut = pd.read_csv("data/my_recording.csv")
df = executer_pipeline_agcounts(df_brut, epoch_seconds=10, frequence_hz=60)
df = ajouter_temps(df_brut, df, epoch_seconds=10, date_reelle=pd.Timestamp("2026-01-01"))
df = lisser_activite(df, epoch_seconds=10)
df = detecter_non_port(df, epoch_seconds=10)
```

## R Analysis

Two R Markdown files mirror the Python application for statistical analysis:

**`main.Rmd`** — interactive working file producing a self-contained HTML document with Plotly figures. Covers temporal profile, global summary, statistics, session details, cycling, and inferential analysis (Kruskal-Wallis, linear trend). Set `RESULTS_DIR` and `EPOCH_SEC` in the Setup chunk before knitting.

**`report.Rmd`** — clean final report for sharing or submission.

Both read from `results/` and expect the standard column names from `pipeline.py`.

```r
install.packages(c("tidyverse", "plotly", "lubridate", "coin", "DT", "scales", "glue", "hms"))
```
